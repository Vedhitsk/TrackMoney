Gradient pill system — from primary_color_gradiant.png

This reference is a different language from the last one, so I have dropped the squircle-and-rim design entirely. What this one actually is, layer by layer:

Full pillRadius equals half the height. Not a squircle — the ends are true semicircles, which is what gives it the soft, friendly read.
Diagonal rampAbout 120°, running top-left to bottom-right. The range is narrow — roughly one step of value — and never reaches black.
Ambient bloomA same-hue halo that is visible above the button as well as below it. It is light, not shadow — which is why these read as glowing rather than floating.
No rim-lightCrucially, there is no bright inner edge and no border. The surface is flat and soft. This is the single biggest difference from the previous reference.
Label onlyCentred text, semibold, generous horizontal padding. No icon tile, no divider, no split action.
Four rolesPrimary (blue), Secondary (indigo→violet), Dark, and Light — a complete button family rather than a single accent.

Glow level — dialled back

You asked for less. Everything below is now set to Subtle: the bloom's opacity dropped from .55 to .26 and its blur from 17px to 13px, the drop shadows roughly halved, and the top sheen went from .13 to .06. Minimal is one further step down if this is still too much. The gradient, shape and geometry are identical in all three — only the light changes.

Against your reference, 1:1

Your image at native size puts each button at 222×78. Mine are built to exactly that, on the same pale-blue ground, in the same 2×2 arrangement.

Mapping the four roles onto TrackMoney

The reference calls its blue “Primary”. TrackMoney's identity is already violet, so there are two honest ways to land this. Both use all four pills; they differ only in which one carries the brand.

A · Violet-led — keeps your identity

The indigo→violet ramp becomes Primary. Blue demotes to Secondary. Nothing about TrackMoney's brand recognition changes.

Primary — indigo → violetFAB · Save · active segment · sheet confirm
Secondary — blueNew account · New category · Add budget

B · Blue-led — the reference as drawn

Blue becomes the brand. Cooler and more banking-conventional, but it retires the violet the app is currently known by.

Primary — blueFAB · Save · active segment · sheet confirm
Secondary — indigo → violetNew account · New category · Add budget
DarkNeutral actions on the light theme
LightThe same neutral actions on the dark theme
My recommendation is A. The gradient does the work of feeling new — you do not also need a hue change to get there, and keeping violet means the icon, the splash and every screenshot you already have stay correct. Blue then earns a real job as Secondary rather than competing with the brand.

Radiusheight ÷ 2 — always a true pill, at every size
BloomA blurred copy of the pill behind it, at Subtle: blur(13px) opacity .26 at 78px tall; blur(11px) opacity .22 on a CTA; blur(12px) opacity .28 on the FAB; blur(8px) opacity .18 on a segment. Plus 0 6px 16px at 16% and 0 2px 5px at 10% in the ramp's mid hue.
Sheenlinear-gradient(180deg, rgba(255,255,255,.06), transparent 55%) — deliberately barely there. On the Light pill it rises to .28, because a white pill needs the sheen to read as curved at all.
Pressedsaturate(1.06) brightness(.93), bloom to blur(7px) opacity .14, translateY(1px) scale(.988). 120ms in, 180ms out.
DisabledGradient and bloom removed entirely — a flat track fill with a hairline. A disabled control must never glow.
React Nativeexpo-linear-gradient for the ramp (needs installing). The blurred-copy bloom has no RN equivalent: iOS uses layered shadowColor in the ramp's mid hue; Android has no coloured shadow before API 28, so it gets an absolutely-positioned gradient halo behind the control instead.
One thing to watch. The bloom is the whole character of this system, and it is the one part Android renders worst. If it has to be dropped on older devices the pills still work — they just read flatter. I would rather that than a fake blur that costs frames on the Add Transaction screen.
